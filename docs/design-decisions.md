## 为什么这样分工

用户确认 Router 代表人在授权内承担理解、指导、交叉复核、验收和交付责任，不退化为纯转发；可确定的不变量优先由程序执行，语义判断保留给模型。见 [责任与程序优先原则](router-accountability.md)，区分设计要求与已实现覆盖。

使用者观察到 Claude Code 更适合理解意图、约束和交付加工，Codex 在明确边界内执行有效；额度也常不均衡。这是实例经验与资源假设，不是普适模型排名或套餐保证。Router 应把人的需求转为清楚的工作包，并检查真实产物，不能只当转发器，也不把每个小修改都强制包装成多 agent 流程。

选择还来自 harness 的适配：Claude Code 已有子任务委派、团队与工作流编排设计，与 Router 的多任务跟踪和验收职责相符。原生功能与 temp/正式 Worker 的类比、人工介入边界、模型选择经验及未验证推断，见 [Router harness 设计依据](router-harness-rationale.md)；它们不是新增运行依赖或功能启用指令。

直接 Codex 维护不应强行绕回 Claude。微任务走直接路径，需要的是合理边界和可观察完成，不是一刀切开关。任一方暂不可用时可经授权独立继续，恢复后同步；不能把双向连续性误写成已经实现自动额度识别或自动切换。

显式指定执行者优先于默认分工，见 [Claude 亲自工作](claude-direct-work.md)。正式 Worker 验收后默认闲置保留，主要 Worker 可 pin；名单按需查找，released 只表示明确解除管理，见 [会话生命周期](session-lifecycle.md)。后台扫描降频和 Desktop 归档联动仍 TBD。

## 记忆放在哪里，为什么不维护三份项目记忆

| 信息 | 权威位置 | 不承担什么 |
| --- | --- | --- |
| 稳定角色与授权边界 | 每个执行用户的短全局入口 | 不放全部项目历史、任务细节或整份流程 |
| 专项步骤与模板 | 薄 skill 索引＋按需指南 | 不让每轮任务常驻全部规则 |
| 项目约束、结构、决定、进度 | 项目共同 AGENTS.md 与链接的权威状态/领域文档 | 不分别维护 Claude 版、Codex 版和共同版事实 |
| Claude 入口适配 | 必要时 CLAUDE.md 薄导入共同入口 | 不复制维护第二套正文 |
| 原生对话与现场状态 | 各原生 session/thread；协调状态库记录登记/任务 | 不用记忆摘要伪装成续聊，不把状态库当知识仓库 |
| harness 的自动记忆 | 辅助索引、偏好与可复用提示 | 不覆盖最新项目文件、人类决定或真实现场 |
| 咨询包、诊断、私有来源映射 | 项目忽略的私有目录或私有运维记录 | 不进入候选公开库或公共事实入口 |

既有项目若只有 CLAUDE.md，先读它并尊重现场，不自动复制或强迁一套 AGENTS.md。共用事实不等于让多个 agent 同时写同一状态文档；临时任务先返回候选结果，由当前维护者整合。行动前刷新相关文件，Git 同步的是源文件，不会自动同步模型上下文或安装版。

## 原生 session 与共享视图的作用

完整创建、可见性、归属、adopt、人工接管与结束语义见 [两类 Worker 与自建 session](session-lifecycle.md)。

持续工作优先续用注册的原生 thread，摘要不能保留同等连续性。temp 为独立短期任务服务，不是天然的 token 优惠档；正式 Worker 复用能减少重复交代背景，也会积累上下文。个人会话由人指名后接管，保留原身份和人改过的名字。

观察到的 Codex 多端同 thread 体验让人和 Router 都能参与；Claude 同时从两个 CLI resume 的分叉体验不能直接类推到它。共享视图本身不是并发锁，仍须检查活跃回合、同步新输入、拒绝旧队列，并保留人工接管/暂停。显示名只是可读标签，真正定位要包含主机、用户/会话存储、项目入口和原生 ID。

## 结构化底层与证据闭环

协调器处理 ID、任务状态、失效和通知，模型只按需看工作包、关键答复和证据。普通回传不搬内部 reasoning 或全量工具流；验收仍要读产物、差异或真实测试。READY/完成事件不等于 ACCEPTED；多个模型互相赞同也不能代替验证。

hooks/角色 guard 用来减少忘规和交互成本，不能称为同 UID 的 OS 安全隔离。Unix socket 是当前通用通信适配，路径、权限和某台机器的沙箱例外属于实例；访问层不用复制这些配置。高权限 Worker 的能力仍受具体任务授权约束。

## 可选顾问与尚未实现的内容

顾问用于能改变具名决策、深度研究或减少昂贵试错的地方。主动建议与实际咨询分开：前者可由规则提醒，后者由人选择并手动发送。回收后先核实关键事实，再回到当前 Router 或 direct maintainer，继续登记 Worker。当前网页模型/额度以当期账户与官方规则为准，不能从浏览器入口推断永久独立额度。

以下先 TBD，不作为首版收工条件：

- 基于日志/多轮停滞的自动推荐信号、自动准备咨询包、推荐收益/频率评估。
- 原生提问/审批的结构化转发、请求归属、过期与多端重复回答处理。
- 全局并发上限可配置与 Router 间公平性；不能仅扩大每 Router 上限而丢掉主机总量边界。
- 长任务通知、ephemeral 断连恢复能力与平台完整验收。

后续改进应说明具体痛点、产物与实测，不因接口看起来能做就立即扩建。新平台或上游协议变化时重新核验；不把 Linux 执行端＋Mac 访问端的成功写成所有 OS 全面通过。

## 为什么单独准备公开候选

源码快照包含已审查的通用运行实现、规则和合成示例，采用MIT。私有实例配置与来源映射仍留在私有运维资料；不复制聊天、主机配置或私有Git历史。后续阶段更新继续审查允许列表与完整 outgoing history，不自动镜像，也不把公开包安装回日常环境。可见性由维护者操作，tag/package/release另行决定。

## 并行工作区的下一步

Claude 亲自完成本职、尊重明确点名并引导不足的 Worker，这三项与默认委派并存。并行采用 Router 判断依赖、程序维护容量与互斥、worktree/输出目录隔离实际变更，再由单写者集成。尚待下一轮实现与 Desktop 验收，见 [DeepSeek 研究](deepseek-superagent-study.md)与[并行设计](parallel-workers-design.md)。

## 旧技能删除不等于旧会话忘记

Claude Code [官方技能生命周期](https://code.claude.com/docs/en/skills#skill-content-lifecycle) 说明 compact 会重附会话里以前调用过的技能指引；删除磁盘入口只停用后续发现，不删除历史上下文。迁移时要明确废止旧指引并加载当前入口；必要时通过共享项目状态新建会话，不篡改原生聊天记录。上下文提醒属于语义引导，不能宣称它拦截了原生恢复。
