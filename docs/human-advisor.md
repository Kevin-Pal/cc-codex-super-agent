# 手动网页版 Pro 顾问

这是可选增强：用户明确要求时，借助网页版可用的深度推理 Pro 模型（例如用户偏好的 GPT-6 Pro）做疑难决策、方案审查或大规模调研。它不替代 Router，不是 Worker 的第四个自动档位，也不要求某个特定套餐。

## 触发与接入

默认由用户手动触发 `/consult-gpt-pro` 或 `$consult-gpt-pro`，自然语言明确要求也可以。在重大方案定稿、大规模调研开始前，或两条实质不同的路线仍无进展时，Router/direct maintainer 应判断顾问能否改变具名决策、核实关键假设或减少昂贵试错；值得时主动建议一次，并说明预期收益与人工转发成本。同一决策没有新证据不反复提醒，不要求每轮任务走检查表。没有用户选择就不主动准备、发送或循环升级咨询。

Codex 的技能元数据设置 `allow_implicit_invocation: false`；Claude 的安装入口另加 `disable-model-invocation: true`。两种入口共享同一份正文与指南。由于 Claude 显式技能不会自动出现在模型可调用列表，用户可以直接输入斜杠命令；自然语言请求先确认用户已选择这条流程，再按客户端支持方式进入，不绕过客户端的显式调用限制。这些规则不授权浏览器/剪贴板自动化。

在 Claude Router 工作流中：Router 定义问题并评审返回结果，Worker 可在已授权工作包内准备材料或核验事实。人直接找 Codex 时：当前 direct maintainer 负责同样的打包和评审，不强制额外调用 Claude。

## 一个可回收的咨询包

默认在当前项目的 `_private/pro-consult/<consult-id>/`，并确认不被 Git 跟踪；若项目已有私有咨询目录则复用，不移动旧档案。材料要能脱离仓库独立读懂，网页顾问不能被假定能访问本地 repo、Worker 对话或未提供的附件。

按需生成，不要求每次填满所有表格：

- `00-manifest.md`：决策问题、范围、关联任务/thread、源版本或文件摘要、所含材料、待核实项、用户新决定与当前状态。
- `01-prompt.md`：目标/非目标、可核实事实、明确假设、约束、已经尝试的路线、同一决策面的编号问题和期望输出。需要调研时给时间范围、原始来源、证据冲突和不确定性要求。
- `01-reply.md`：用户交回的原始回答；追问另编号。不主动读取剪贴板或网页。
- `90-follow-up.md`：关键主张的事实/假设/建议、核验依据、采纳/修改/拒绝理由，以及回到当前工程的最小增量任务；仅在要落地时创建。
- `99-outcome.md`：决策影响、实际核验、遗留问题与关联任务验收；纯咨询到此即可，不强行创建 Worker。

只提供解决问题所需的最少代码摘录/日志/资料，优先脱敏并注明来源；已有任务授权不等于可以上传无关私密内容。给用户清楚的复制文本和必要附件位置即可，不把文件、剪贴板和网页操作强行捆绑。

## 回收与落地

回答不完整或缺关键附件时先标记缺口，不能补造回答。可以约定结尾标记辅助发现截断，但不把标记当作内容正确性的证据。

按后果核实关键事实和研究来源；把顾问建议与已验证事实分开。版本或人类决定改变后重新对表，不把旧方案当当前规格。针对重要决定记录最小 claim ledger，简单咨询不强制长表。

继续原工作线时先同步项目事实、外部输入和当前 turn，再给登记的正式 Worker 发增量 work package；不新建替代 thread，不绕过暂停/接管，不调用旧 codex-delegate 或一次性 exec。Router 或 direct maintainer 核验实际产物后才验收，顾问和 Worker 相互赞同不能代替证据。

追问要能关闭具体未知；连续追问没有新证据或决策收益时收束，并将需要人的偏好/风险取舍交还用户。咨询回复不是对发布、生产操作或新授权范围的批准。

## 用量与公开表述

用户经验是：对于同时拥有网页版 Pro 权益的 Codex 用户，手动借用深度推理顾问，有时能以较少人工转发换取更充分思考或调研，减少执行侧试错。这是使用动机，未做成本/效果基准，不是保证最强或更省的普遍结论。

不能从“在浏览器里”推断额度独立。2026-11-02 核查的[官方说明](https://learn.chatgpt.com/docs/pricing)已经明确 ChatGPT Work 与 Codex 共用用量；Chat 的 Pro 模型及独立消息额度是否适用，以当时的产品入口、账户页面和官方规则为准，可能变化或合并。不要把 Web Chat、Web Work、订阅包含量和 API 额度混成同一承诺；不写死固定每周次数或永久零 Codex 消耗。打包、核验与后续执行仍消耗实际参与的 Claude/Codex 额度。

## 可选安装与旧入口

主框架不要求这个顾问技能。人工安装时给 Codex 保留上述显式调用元数据，给 Claude 的同源 SKILL frontmatter 增加 `disable-model-invocation: true`，支持文件一起复制；不要重写 provider、登录或浏览器配置。用户级现有技能先备份并审查再替换。

旧 codex-delegate 的跳转入口也会占发现列表；确认由新 Router 完全替代后，将整个旧目录移到技能扫描目录以外的私有备份区，而不是仅改名为另一个技能目录。不要删旧咨询包、聊天或旧任务日志；它们只停止接收新记录。

自动打包、根据日志/任务状态生成触发信号、推荐去重与收益评估先列 TBD。当前只有规则级主动建议，不宣称有确定性的自动触发引擎；不因未来功能尚缺而阻塞日常工作。
