# 执行端、访问端与工作目标

本框架把“agent 在哪里运行”和“人从哪里访问”分开。项目入口目录、Claude Code Router、Codex 会话/执行后端以及本框架的配置、技能、协调状态，放在同一执行端、同一用户环境中；人可以在执行端本机，也可以从另一台电脑访问。

这里的 Codex 后端是 CLI/app-server 及其会话和工具运行时，不要求把模型权重部署在该机器，也不要求 GPU。Codex Desktop 是人使用的 GUI，远程模式下可以只在人的电脑上运行。

## 三个位置

| 位置 | 承载什么 | 是否必须与其他位置相同 |
| --- | --- | --- |
| 执行端 H | 项目入口目录 P、Claude CLI、Codex 原生后端、ai-work/技能/配置与私有状态 | 本首版把这些放在同一主机、同一用户/会话存储，接入同一原生 runtime |
| 访问端 U | 人的终端和 Codex Desktop | 可以就是 H，也可以是其他电脑 |
| 实际目标 T | 要修改的代码、处理的数据、GPU 实验、部署服务等 | 可以在 H，也可通过已授权的 SSH/工具位于其他机器 |

P 是项目和会话的稳定入口，也是默认 cwd、共同规则与知识的入口；它不要求所有实际工作文件都放在 P 下。例如可以在 H 的一个运维项目里管理会话，再让 Worker 按任务操作 T 上的指定目录。工作包要把“会话入口”和“实际主机/路径/权限/产物”写清，不因为入口路径相同就推断实际目标相同。

通过普通 SSH 操作 T 时，T 不必安装整套 agent 框架；如果把 Router/Codex 运行时迁到 T，T 就成为新的执行端，需要相应安装和会话迁移。不要仅为了操作另一台机器就反复改原生 thread 的入口 cwd。

## 两种访问方式

| 操作 | 本地一体：U = H | 远端常驻：U ≠ H |
| --- | --- | --- |
| Router | 在 P 运行本地 Claude CLI | SSH 到 H，在 tmux 中进入 P 运行 Claude CLI |
| Worker GUI | Desktop 添加本机 P | Desktop 绑定 H 的 SSH 连接，添加远端 P |
| Project 名称 | 任意可读标签 | 任意可读标签，与另一台电脑名称可不同 |
| 日常交互 | 在 CLI 与 Router 说话，在 Desktop 与 Worker/个人 session 说话 | 同样的两个入口与协作规则 |
| 框架安装 | 安装在 H 当前用户 | 同样安装在 H 当前用户；纯访问用的 U 不必再装远端的角色规则 |
| U 关闭或休眠 | 若 U 也是 H，执行环境也可能停止 | H 和相关进程仍运行时，已派发工作可继续，结果留在 H |

远端方式主要多出 SSH 连接和远端 Project 的初次设置，日常派活、观察、直接交流、接管和验收不应变成另一套流程。官方 SSH 模式是在远端启动 Codex app-server，并使用远端文件与 shell；不是把远端文件复制到访问端后偷偷另开一个 Worker。[官方远端说明](https://learn.chatgpt.com/docs/remote-connections#connect-to-an-ssh-host)。

本地一体与远端常驻是同一架构的两种布置，不意味着所有平台/版本已经分别验收。0.2.0 当前真实试点是 Linux 执行端＋Mac Desktop 远端访问；本地一体使用时仍需核对本机原生 control socket、版本和相同 thread 的可见/可聊。参见 [验证范围](runtime-validation.md)。

## 纯访问端无需安装 Worker 角色

如果 U 只通过 Desktop Remote 和 SSH 访问 H，U 使用产品默认远端连接方式即可：Desktop 添加同一 SSH 主机/用户下的远端 P，终端 SSH 到 H 后进入 P，运行/恢复同一个 Claude Router。框架安装、全局规则、角色技能、hooks、协调器、登记状态都在 H；不要把 H 的隐私白名单、provider 或角色安装复制到 U。项目会话归属还取决于远端用户和 Codex 会话存储（如 CODEX_HOME），不能只比较显示名或路径字符串。

某台 U 可以同时用于本地独立 Codex 维护。为该用途安装 Codex 协作规则和 Worker skill 是可选便利，与远端链路无关；用户直接找它时仍是 direct maintainer。当前 `install --role worker` 会复制完整发行文件、安装 ai-work、Codex 入口和 skill，但不因安装就创建原生 Worker 或自动常驻一个 daemon。这个安装角色名表示装哪些规则，不表示机器已成为受 Router 调度的 Worker。

开源安装说明应以“执行端安装＋访问端原生连接”为必需流程，将上述本地辅助规则作为明确可选项。未来可以再拆分 rules-only 安装或调整安装角色命名；本次只澄清边界，没有自动卸载已有实例。

## 推荐常驻执行端

需要长任务、跨电脑使用或人关掉笔记本后继续工作时，优先选择网络稳定、不会随人休眠/关机的常开主机作为 H，通常是 Linux 服务器；Claude CLI 放在 tmux，Codex 原生后端与协调器留在 H。各访问端连接同一远端用户、会话存储和 P，不复制多套账号配置或聊天文件。

tmux 保留终端进程，适合 SSH 断开后返回原现场；它不让机器关机后继续执行，也不自动恢复一次系统重启前的全部进程。H 上的运行进程、网络、登录状态和额度仍是持续工作的条件。

关闭 U 不等于关闭 Router；结束 Claude 进程则意味着 Router 暂时不再规划、验收或加工新交付。Codex 已在运行且有足够授权/额度的任务可以独立完成，结果由协调层保留；人可以直接访问正式 Worker。恢复 Router 后先同步新输入、产物和项目知识，再继续。这不是 Claude 关闭后还有一个隐形 Router 自动工作。

本机写入互斥围绕已纳管工作树，不是跨所有目标服务器的分布式锁。不同入口 P 若操作同一个 T，需要按实际目标协调写入和资源；SSH/GPU 长作业也应有可定位的作业状态与恢复方法。
