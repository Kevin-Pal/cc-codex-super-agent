# Reviewed snapshots, no private-history mirror

1. Select a tested, immutable development revision and an explicit allowlist of generic code, rules, guides, skills and synthetic tests.
2. Export files into a clean review workspace without .git, ignored files, credentials, runtime state, logs or personal project memories. Keep exact source-to-public mapping in private operations records.
3. Generalize instance-specific migrations and defaults without changing live operator settings. Record distribution-only adaptations and reconcile genuine runtime fixes with maintained development lines.
4. Review files, commit identities and the complete outgoing history. Regenerate skill references, run proportionate tests and inspect a source archive/fresh clone.
5. Commit the reviewed public snapshot with an appropriate public identity. Never merge or push a private branch to update this repository. Keep the private and public remotes unambiguous.
6. Source updates do not install themselves. Verify installed/runtime versions separately when an operator chooses to upgrade.
7. Keep publication/package/tag automation disabled unless explicitly requested. The owner handles visibility for the first snapshot.

Future maintainers may develop generic improvements here; private operator configuration and Claude's internal provider maintenance do not belong in this codebase. Local pre-push checks assist review but do not replace it.
