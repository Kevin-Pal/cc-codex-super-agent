# Why use Claude Code as Router?

The workflow benefits from Claude Code's intent-oriented interaction and orchestration concepts while retaining native Codex execution sessions and Desktop intervention. Subagents/teams and other native orchestration features are useful precedents, not dependencies or features enabled by this project.

The Router is responsible for planning, bounded instructions, cross-checking, repairs and delivery. A sufficiently capable model matters when one session tracks multiple workstreams; users choose their own model/effort. Capability depends on task and configuration, so this project does not hard-code a model ranking, minimum paid plan or cost claim.

Temporary Workers resemble disposable subtask execution; formal native sessions preserve a longer direction and an interface for human intervention. These are design analogies, not assertions that the two harnesses have identical semantics or UIs. Shared conversation visibility does not replace writer coordination.

The independent harnesses can supply useful cross-checks and balance an operator's available usage, but agreement is not evidence of correctness. Explicitly Claude-assigned review/design stays with Claude; clear execution boundaries help Codex; results still require observed checks.
