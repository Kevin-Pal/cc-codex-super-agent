# Model routing and available usage

Worker task profiles are easy, hard and xhard; the runtime resolves supported model/effort choices against the native catalog or an operator-supplied codex-tier helper. The helper is optional and not shipped as an account-specific configuration. Use doctor to inspect the actual mapping. No model name or plan entitlement is permanently guaranteed.

Use simple profiles for independent batches, the usual capable profile for daily implementation and a stronger profile for genuinely difficult bottlenecks. Persistent/temporary lifecycle is independent of model tier. The person chooses the Claude Router model and effort in the native interface; this framework does not switch providers or account settings.

A capable Router must understand intent, track constraints, guide repairs and independently accept evidence. When available usage differs between harnesses, the work split can use that asymmetry without making promises about prices or quotas. If one side is temporarily unavailable, the other may continue within authorization and reconcile later; automatic quota detection/switching is not implemented.

Check current official product documentation for access, pricing, limits and account terms. This repository includes no personal account experience as a guarantee of availability, anonymity or subscription safety. See [harness rationale](router-harness-rationale.md) and [quota continuity](quota-continuity.md).
