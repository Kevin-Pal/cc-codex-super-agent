# 规则加载与两步安装

2026-11-02 分层设计。0.2.0 已实现技能、全局入口/hooks 与版本化用户安装器，未引入 plugin/MCP 分发层。实际操作见 [安装与运行](runtime-operations.md)，验证见 [范围](runtime-validation.md)。

## 四层职责

| 层 | 内容 | 加载与责任 |
| --- | --- | --- |
| 短入口 | Router/Worker 身份、共享项目记忆入口、技能触发、暂停与接管边界 | 全局常驻，包含角色所需的最小共同约定 |
| Skill 入口与索引 | 路由判定，以及什么情况读取哪份指引或调用哪个命令 | 元数据供发现，正文在相关场景加载 |
| 专项参考与模板 | 创建/续跑/点名接管/临时任务、返工、验收、恢复、项目记忆 | 每次只读取当前场景需要的部分 |
| 程序接口与 hooks | ID/参数校验、状态转换、去重、单回合、事件/结果持久化与回传 | 确定性检查，不能仅靠模型记住调用规范 |

关键角色与指令优先级不能只藏在可选 skill 中，否则角色已经漂移时可能根本不会加载。相反，完整协议/历史日志/所有操作手册不塞进全局文件。短入口提供明确触发规则，运行层在实际调用处拒绝不合法状态；hook 检查受支持的工具动作，不能被说成同 UID 的绝对安全边界。

## 首版包装选择

先以一个版本化 Git 仓库维护共同规则、模板与通用 runtime，提供两份很薄的角色技能入口：`claude-codex-router` 和 `claude-codex-worker`。前者导航路由/会话/提示/验收，后者导航执行/人工介入/共享知识。专项流程作为引用，不把每个动作拆成一份全局 skill。安装到两种客户端所需目录时共享同源内容，适配入口语法，不维护两套协议。

全局入口优先控制在每个角色约 20–30 行；skill 入口只给索引与简短执行原则。行数是设计目标，不是效果保证。实际检查所有 skill 的描述列表、重复导入、启动 token 和一次普通任务的额外加载量；与当前基线比较后再收敛预算。

Skill 是工作流知识，plugin 是安装分发包装，MCP 是工具接口；三者不是互相替代的选项。首版用技能包与统一 CLI 适配更容易审查。若 Claude 的可靠工具调用/通知确实需要 MCP，可在同一 runtime 上加薄 adapter；它不能独立起另一套 session manager。plugin 可在安装流程稳定后包装相同技能与适配，不作为这轮定方向的前置条件。

两家产品目前都支持技能目录、元数据发现与支持文件按需加载，但字段/路径与自动触发机制仍有差异。标准化共同正文，客户端专有配置放 adapter，不能假定同一包在两端原样安装就自动一致。[Codex skills](https://learn.chatgpt.com/docs/build-skills)、[Claude skills](https://code.claude.com/docs/en/skills)。

## 面向使用者的两步

1. **接入入口和必要配置**：安装器先只读发现全局源、生成链、冲突与版本，展示所需差异和回滚；经部署授权后合并小段角色入口，以及确有必要的调用/通知配置。保留已有全局规则、隐私、登录和 provider 管理方式，不能下载后整份覆盖。
2. **安装同一版本的技能与组件包**：固定发布版本/commit，安装所需角色 skill、通用命令及其必要 adapter；执行 doctor 与角色/加载检查，登记已安装版本。升级与卸载用清单追踪自己的文件，支持幂等执行和回滚。

这两步是用户界面的简化，不强迫用户手改内部路径。当前由安装器的预览/应用过程合并完成，具体命令见运行手册。只查看/直接维护的 Codex 不必运行 Claude Router 的后台组件，访问已有远端 Worker 仍使用 Desktop 原生远端能力。

项目首次接入只需指向/补齐其共同 `AGENTS.md` 与权威状态入口；不让每个研究仓库复制整套全局规则或 runtime。Git 更新源文件不自动部署；安装锁定版本，不能 pull 后悄悄改变正在运行的协议。

## 防止长上下文失效

- 新会话/恢复时校验入口、技能和 runtime 版本；具体行动时按场景读指引，不依赖很早前的一次长提示。
- 调用前由命令或工具 schema 校验 mode、目标 thread、当前 turn、任务 revision 与权限模板。禁止用未确认的新参数试错到成功。
- 开始前返回明确 task/turn 身份，结束事件写入私有状态库；重复通知不会重复派活。Router 缺席则保存结果等恢复，不伪装成已唤醒。
- 权限和角色 guard 与已有维护源合并、受影响用例实测；仍允许已批准的 router-direct 短路径，不用一刀切 hook 阻碍 Router 本职。
- 规则只保留有观察依据的约束；发现冗余/矛盾时在源头修改，不能靠每次再叠一段提醒补丁。

## 发布验收

两种角色能按两步流程完成安装；重复安装无多份导入。普通小任务不读整份运行手册，续跑/接管/临时任务各能触发正确指引。必需技能缺失或版本不兼容时给明确修复，不静默回到随意调用。卸载仅移除本包拥有的入口和文件，不清空聊天或共享项目知识；受保护 provider/隐私配置保持原语义。
