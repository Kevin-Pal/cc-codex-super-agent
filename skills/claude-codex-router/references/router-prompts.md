# Router 给 Worker 的指令设计

2026-11-02 草案。目标是让 Claude 把人的模糊意图转换成可靠的执行约束，减少越界、漏验收、反复确认与返工。暂不把“快或自信”当作某个模型的固定属性；以后用实际任务评价改善。

## 指令分层

稳定的角色、证据和授权约定在入口/skill，项目知识在共享文件，任务包只写本轮目标与差异。Router 先确定直接处理、临时 Worker、正式 Worker 或用户点名会话，再选档位。短任务可以是几句话，不要求每次填全部元数据。

首次指令最少讲清：要交付的用户结果、关键输入/约束、授权范围、何时算完成。已有会话的后续指令先同步人的新决定，只补本轮差异；运行层自动补 thread、turn、任务 revision、配置和文件版本，不让 Claude 手写易错 ID 或 shell flags。

## 让谨慎落到具体动作

| 容易出现的偏差 | Router 应写出的可执行约束 |
| --- | --- |
| 沿用猜想就动手 | 先核对与任务有关的现场基线，区分已确认事实与影响方案的假设；高影响假设先调查 |
| 顺手改无关模块 | 列出允许改动的对象、必须保留的行为和外部动作授权；可逆实现细节自行处理 |
| 只交一个补丁便停止 | 完成定义包括必要的运行/检查/查看实际结果及修复失败，交付可审查产物 |
| 用 `active`、退出 0 或模型共识证明成功 | 指定用户实际关心的可观察结果；无证据的项标未验证 |
| 把测试改到刚好通过 | 保持需求和验收语义；需要改测试时说明依据，验收不能随实现静默移动 |
| 无止境确认或研究 | 在授权内连续完成可逆步骤；只把改变目标、授权或重大后果的分歧交回 Router |
| 读到很多资料但无法判断 | 对不熟悉、变化快或明确要求调查的问题查官方与一手社区来源，给版本、日期、适用条件和推荐 |

这不是每轮都追加的口号清单。Router 根据实际风险挑选相关约束，给 Worker 足够的实现自由。不要索取完整内部思维链，索取关键判断、证据、产物和仍需决策的事项即可。

## 首次和返工的沟通

先尊重用户指定的执行者：点名 Claude 亲自优化、美化或交叉核验时，Claude 完成核心判断和加工，不把同一要求原样返派给原 Worker。Worker 有缺口时给出具体设计/证据/修复约束，避免空泛循环；Claude 实质写入的现有授权路径见 [亲自工作](../../../docs/claude-direct-work.md)。

一般任务用 [任务模板](../../../templates/task.md)，续跑用 [增量模板](../../../templates/followup.md)。同一逻辑工作线优先续用正式 thread；批量一次性任务可用临时 Worker；独立审核隔离实现历史。

有重大未知或生产应用边界时，把“调查/准备”与“应用”区分；不机械要求所有工作先停一次等批准。用户已批准范围内的普通实现、调试和核验应连贯完成。

返工说明“原要求 → 实际证据 → 具体差距 → 允许的修复范围 → 重验方式”。不要只说“再仔细点”，也不让 Worker 因一次调用错误就丢掉上下文或自动升档。

```text
沿用这个 Worker。用户刚确认保持现有导出字段，最新决定在项目状态文档中。
上一轮的服务状态检查还不能证明导出成功。请核对实际接收路径，使用现有脱敏样例完成一次导出并读回，给出字段一致性的结果。
可修复当前工作树内的导出实现与相关检查；保留无关改动。未经新的授权，不应用到生产实例。
完成后给产物路径、观察到的结果、尚未核验的项，并更新同一份项目状态。
```

## 验收与消耗

Worker 回传先给 ready/blocked/failed，再给产物、实际检查、未验证项、共享知识变更和人工新决定。Router 看目标、产物和关键证据，按后果决定是否独立复核；普通小任务不固定多叠一层模型审核。

后续试点建立少量有代表性的任务：模糊目标、旧记忆、人工中途纠偏、环境错误、普通修复、明确微任务、批量研究。比较旧指令与新指令的完成质量、越界/漏验收、人工介入次数、返工次数、总 tokens/时延和重复读入量。保持输入与评价标准一致，不仅看第一轮速度；没有实测前不承诺节省比例。

## 依据

OpenAI 的近期经验建议缩短技能描述、按需加载指导，并为任务写清边界和完成定义，避免积累与当前模型行为不匹配的冗长旧规则。本方案采用这种方法，但同一套约束仍需在 easy/hard/xhard 上分别试点。[官方经验](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。

## 可选网页顾问的主动建议

重大方案定稿、大规模调研开始前，或两条实质不同的路线仍无进展时，判断一次人工网页咨询能否改变具体决策或降低高成本试错。值得时主动简短建议一次；同一决策没有新证据不重复提醒。用户选择后再按 [手动顾问流程](../../../docs/human-advisor.md) 打包，不自动操作网页/剪贴板。触发引擎、自动打包和日志信号先 TBD，不要求每轮加载完整咨询指南。
